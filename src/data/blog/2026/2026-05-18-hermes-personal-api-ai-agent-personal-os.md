# Hermes Personal API：我的 AI Agent 个人操作系统

## 项目背景

我现在的核心工作是用 AI 为企业提效。这个方向最难的地方不是找到一个好工具，而是让工具长期理解我的工作、项目、偏好和上下文。

Hermes Personal API 是我给自己搭的一层个人操作系统：它把 Hermes Agent、Obsidian、飞书和日常项目连接起来，让 AI 不只是一次性回答问题，而是能持续参与我的工作。

## 真实问题

- **上下文会丢失**：普通对话工具每次都要重新解释背景，长期项目很难连续推进。
- **项目资料分散**：工作记录、项目文档、会议纪要、方法论和复盘经常散在不同工具里。
- **AI 很容易停在建议层**：如果没有明确的执行入口和沉淀机制，AI 产出很难变成下一次可复用的经验。

## 目标

| 目标                         | 验收方式                                            |
| ---------------------------- | --------------------------------------------------- |
| 让 AI 理解我的长期工作上下文 | 能基于已有身份、偏好和项目资料继续推进任务          |
| 把周复盘变成项目沉淀         | 每周博客可以继续抽取成项目档案或方法论              |
| 连接真实工具链               | 能围绕 Obsidian、飞书、代码仓库和内容发布形成工作流 |

## 工具链

- **Hermes Agent**：负责长期记忆、任务推进和 Agent 工作流。
- **Obsidian**：承载个人知识库、项目资料和方法论沉淀。
- **飞书 / Lark CLI**：连接会议、文档、表格和协作流程。
- **Codex / Claude Code**：处理代码实现、项目分析和工程化落地。
- **Astro Blog**：把可公开的项目过程、工具使用和方法论沉淀成职业成长档案。

## 当前公开成果

- 建立了个人成长档案站点，用来区分真实博客、项目档案、工具栈和方法论。
- 将 Hermes 作为重点项目案例持续记录，而不是只作为一个工具名称出现。
- 为每周复盘和项目档案建立了固定模板，让后续积累更容易持续。

## 当前阶段

这个项目还在进行中。当前重点不是把它包装成完整产品，而是持续验证：

1. Hermes 能不能帮助我更快整理项目上下文。
2. 周复盘能不能稳定转化成博客、项目档案和方法论。
3. 真实工作里的工具链能不能被 AI Agent 更自然地串起来。

## 复盘

### 做对了什么

- 先围绕自己的真实工作流搭系统，而不是为了展示而堆工具。
- 把 Agent、知识库、博客和项目档案放在同一个长期积累方向里。
- 保持公开边界，只展示职业上可公开的过程和方法。

### 还要继续补的地方

- 需要持续写每周复盘，让系统真正有稳定输入。
- 需要把更多项目过程整理成可公开案例，而不是只留在内部记录里。
- 需要给每个项目建立更清楚的结果证据和阶段复盘。

## 可迁移方法

这个项目给我的一个重要方法是：**先把 AI 放进自己的真实工作流里，再谈对外输出。**

只有工具真正参与了任务推进、资料整理和复盘沉淀，它才会从“好用的聊天工具”变成“可以持续积累的工作系统”。
